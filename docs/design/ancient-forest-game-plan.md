# 고대 숲 퍼즐: 장치 이해와 빛의 반응 개선안

2026-09-13 · 게임 기획 검토 · 코드와 실제 배포용 원본 아트 기준

## 진단

사용자가 본 `R / G / B`는 빨강·초록·파랑을 구별하는 배지다. 퍼즐을 풀 때 영문자를 입력하는 기능은 없다. 수정은 지나가는 빛의 색을 바꾸고, 색의 문은 자신과 같은 색의 빛만 통과시킨다. 특정 색을 요구하는 생명도 같은 규칙을 사용한다. 내부 레벨 데이터는 수정에 `r/g/b`, 문에 `A/B/C`를 쓰지만 플레이어는 이 데이터 기호를 알 필요가 없다.

`src/render/entities.js`의 `colorMark`는 수정·문·목표에 영문 배지를 그린다. 반면 `src/ui/strings.js`의 첫 설명과 17번 퍼즐 튜토리얼은 `r/g/b`와 `A/B/C`를 함께 나열한다. 동일한 물체에 서로 다른 기호가 붙은 것처럼 보이고, 세계관보다 구현 규칙이 먼저 보인다.

사다리처럼 보이는 물체는 색의 문이다. 실제 `art/renders/sprites/gate-r-v1.png`를 보면 두 세로 기둥과 세 가로 막대가 정사각형 받침 위에 놓여 있어 사다리로 읽힌다. 빛이 통과해도 이 막대는 이미지에 구워져 있어 사라지지 않는다. 현재 통과 상태는 옆쪽 빛만 추가하므로 열린 문이라는 피드백이 부족하다.

빛이 목표 앞에서 끊기는 현상은 `src/sim/tracer.js`가 목표에 닿은 마지막 구간에 `endFrac: 0.5`를 넣고, `src/render/beams.js`가 이를 셀 중심 간 거리의 절반으로 그리기 때문이다. 물체 중심에 수신되는 빛이 보여야 한다. 성공 판정은 현재 연결 상태인 `satisfied`에 있고, 한 번 깨어난 외형은 `litAt`에 남는다. 두 상태를 혼용하면 연결이 끊어진 생명이 계속 성공 중인 것처럼 보인다.

## 이번 패치의 우선순위

| 우선 | 변경 | 구현 범위 | 유지해야 할 것 |

| 2 | 분할기는 `갈림 거울`, 색의 문과 포털은 `색의 문`/`연결문`으로 구별 | 설명 문구 | 내부 `splitter`, `gate`, `portal` 타입 유지 |

색 배지를 단순히 없애면 색각 차이가 있는 플레이어의 퍼즐 단서가 사라진다. 따라서 색과 독립된 표식을 모든 표현 모드에 제공한다. 표식은 목표·수정·문에서 모양과 방향을 같게 유지하고 장식적인 복잡한 룬으로 바꾸지 않는다. 빛 색상 보조 설정은 선의 무늬를 추가하는 역할로 설명한다.

## 적용할 한국어 문구

- 기본 안내: **거울을 눌러 빛의 방향을 바꾸고, 모든 생명에게 빛을 이어주세요.**
- 갈림 거울: **갈림 거울은 빛을 곧게 보내면서 옆길로도 나눕니다. 두 갈래를 모두 살펴보세요.**
- 색 튜토리얼 제목: **같은 표식으로 빛을 이어주세요**
- 색 튜토리얼 본문: **수정은 지나가는 빛을 자신의 색으로 물들입니다. 색의 문은 같은 색의 빛만 통과시켜요. 수정과 문, 생명에 새겨진 같은 표식을 따라 빛을 이어주세요.**
- 표식 범례: **마름모 · 붉은 빛 / 잎 · 초록빛 / 물방울 · 푸른 빛**
- 문 상태: **같은 색의 빛을 기다리는 문 / 빛이 통과하는 문**
- 연결문: **빛이 연결문에 들어가면 짝이 되는 연결문에서 같은 방향으로 나옵니다. 문 아래의 선 개수가 같으면 한 쌍입니다.**
- 힌트 버튼: **힌트**; 접근성 이름 **다음 거울 힌트 — 사용하면 별은 최대 2개**
- 무료 안내 버튼: **장치 안내**; 보조문구 **안내를 읽어도 별과 이동 횟수는 바뀌지 않습니다.**
- 색상 보조 설정: **빛의 색을 선 무늬로도 구분**

17번 첫 색 퍼즐의 카드에는 텍스트만 두지 말고 실제 수정·문과 동일한 표식을 사용한 작은 도해를 넣는다. 도해를 닫은 뒤에도 장치 안내에서 다시 볼 수 있어야 한다. 한 번 본 튜토리얼을 재강제하거나 기존 `tipsSeen`을 초기화할 필요는 없다. 무료 안내는 정답, 회전해야 할 위치, 해답 배열을 노출하지 않는다.

## 시각·동작 확인 기준

1. 17·18·22번 퍼즐의 조각 아트/간결한 도형 모드에서 수정·문·목표의 표식이 일치한다. 작은 셀에서도 마름모·잎·물방울을 서로 구별한다.
2. 흰빛 및 다른 색 빛은 문 앞에서 멈추고, 일치하는 빛은 중앙 통로로 이어진다. 열린 문을 가로 막대가 막아 보이지 않는다.
3. 네 방향에서 목표에 들어오는 빛이 수신점까지 이어진다. 입사광과 목표의 후광 사이에 빈 틈이 없다.
4. 정답 색 도착과 유지, 다른 색 도착, 한 번 깨어난 뒤 연결 끊김을 각각 구별한다. 전역 화면 번쩍임을 성공의 유일한 단서로 쓰지 않는다.
5. 390px 모바일에서도 장치 안내가 HUD나 퍼즐을 상시 가리지 않는다. 안내는 기존 모달 관리·초점 이동·게임 입력 차단 규칙에 참여한다.
6. 안내 열람 전후 이동·힌트·별·저장 데이터가 동일하다. 300개 퍼즐 해답과 진행 데이터 형식은 바꾸지 않는다.

## 조사 근거

- 색상 정보에는 모양·무늬·표식·텍스트 등 독립적인 단서를 함께 제공한다. 적용: R/G/B 삭제 후 모양을 남기며 수정·문·목표가 같은 모양을 공유한다. [Microsoft Xbox Accessibility Guideline 103: Additional channels for visual and audio cues](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/103).
- 설명을 실제 상호작용 맥락과 연결하면 이후 기억해서 적용해야 하는 부담을 줄인다. 적용: 첫 색 퍼즐에서 실제 장치와 같은 도해를 보여 주고 언제든 재열람한다. [Game Accessibility Guidelines: Include interactive tutorials](https://gameaccessibilityguidelines.com/include-interactive-tutorials/).

위 자료는 안내 방식의 근거이며 외부 게임 아트나 레벨을 복사하기 위한 원본이 아니다. 이 문서는 구현 전 기획안이다. 완료 판정은 실제 게임 화면과 별도 검증 결과로 남긴다.

## 구현 인계 — 2026-09-13

- 표식의 원본 경로를 `src/ui/colorMarks.js`에서 공유한다. `entities.js`의 캔버스와 안내 SVG가 같은 좌표로 마름모·잎·물방울을 그린다.
- `src/ui/deviceGuide.js`는 현재 퍼즐의 장치 종류와 터치한 고정 장치를 읽는다. 해답·힌트 서비스를 호출하지 않는다.
- HUD의 장치 안내는 현재 퍼즐에 있는 장치를 보여 준다. 수정·문·생명·빛의 샘·연결문을 누르면 해당 장치만 설명한다. 거울과 갈림 거울의 탭 동작은 회전으로 유지한다.
- 안내는 기존 모달 관리와 초점 이동에 참여하며, 토스트와 튜토리얼을 겹쳐 보여 주지 않는다. 설정 및 첫 안내와 중첩해서 열리지 않는다.
- 27개 관련 테스트 통과: 새 안내 테스트 5개, 기존 UI·언어·게임 판정 테스트 22개. 안내 전후 게임 상태·진행 저장 객체 불변, 장치별 열람, 초점 고정, 모달 중첩 차단, 튜토리얼 재개, 색 표식 일치가 포함된다.
- 새 Blender 석문은 부모 에이전트가 제작한다. 런타임은 중앙에만 반투명 봉인을 추가하며 같은 색 빛이 연결되면 봉인을 제거한다.
- 실제 브라우저 화면 검증과 최종 통합 검토는 부모 에이전트에게 인계한다. 위 테스트 결과는 시각 검수의 대체 자료가 아니다.
