# 빛 발사 v3 — 즉시 연결과 지속 발광

2026-09-14 · 구현 기록

## 요청과 변경

사용자는 최근 추가한 첫 발사 느낌을 이전처럼 바꾸고, 빛이 계속 발사되고 있다는 인상을 더 분명하게 만들기를 요청했다. `72acec8`의 광선과 `e355b1b` 이후 연결 선단 연출을 비교했다. 최근 버전은 시작 시 경로를 따라 전체 길이가 천천히 늘어나므로, 이미 판정된 연결을 화면에서 기다려야 했다.

이번 버전은 **첫 프레임부터 현재 광선의 전체 경로를 보여 준다.** 색의 문과 목표도 같은 프레임에 실제 연결 상태를 표현한다. 경로 길이를 늘리거나 전체 광선을 서서히 나타내는 발사 연출은 사용하지 않는다. 첫 시작·다음 퍼즐·다시 시작에 같은 원칙이 적용된다.

지속 발사감은 경로를 지우거나 끊는 대신 이미 연결된 빛 위에 더한다.

- 광원 앞쪽에 밝은 중심선과 길쭉한 발광 영역을 놓고, 낮은 강도의 동심 광륜을 더했다. 광원의 실제 방향에 맞춰 함께 회전한다.
- 광선은 넓고 약한 외곽 빛, 색을 읽을 수 있는 중간층, 가는 밝은 코어로 구성한다. 색각 보조의 선 무늬는 유지한다.
- 약 2.65칸 간격의 작은 빛이 초당 1.45칸 속도로 흐른다. 경로별 거리를 공유하여 거울·갈림·색 변화에서도 이어지고, 교차하는 다른 경로로 옮겨가지 않는다.
- 각 칸은 같은 이동 띠와 자기 구간의 교집합을 그린다. 앞부분이 다음 칸에 들어가도 이전 칸의 꼬리가 바로 사라지지 않는다.
- 막힌 곳과 목표에서는 이동하는 작은 빛을 흡수하듯 줄이되, 연결된 광선 자체는 계속 보인다.

## 유지한 동작과 경계

목표 중심까지 이어지는 종점, 불투명 장치 위의 접촉층, 현재 연결의 작은 후광, 잘못된 색에 성공 후광을 주지 않는 규칙, 포털 양 끝 사이에 물리적인 직선 광선을 그리지 않는 규칙은 유지했다. 한 번 깨어난 외형과 현재 연결 상태의 구별도 유지한다.

늦게 도착하는 선단을 위한 목표 파티클 숨김 필터는 필요 없어져 제거했다. 원래 파티클 시스템의 그리기와 수명 관리를 그대로 사용한다. 게임 판정·보상·저장·오디오에는 변경이 없다. `game.js` 변경은 시작 시 `beamReveal=1`로 두고 이후 길이를 키우던 표현 제어를 제거한 부분뿐이다.

움직임 끄기 또는 OS의 모션 감소에서는 흐르는 작은 빛과 광원의 숨쉬기를 멈춘다. 전체 광선과 정적인 발광은 계속 보여 퍼즐을 읽을 수 있다. 외부 이미지·라이브러리·셰이더·새 이미지 생성 모델은 사용하지 않았으며 모두 프로젝트에서 작성한 Canvas 도형이다. 광원에 매 프레임 이미지나 그라데이션을 새로 만들지 않는다. 전체 광선 프레임도 경로가 바뀔 때까지 캐시한다.

## 검증과 인계

실행: `node --test tests/beamContact.test.mjs tests/gameSemantics.test.mjs tests/backgroundMotion.test.mjs tests/engine.test.mjs` — **42개 통과**.

확인 항목은 첫 프레임·재시작의 즉시 연결, 300개 퍼즐의 초기/완료 광선, 네 방향 목표 종점, 색문 차단, 갈림·교차·포털·루프, 정답/오답 색과 재연결, 모션 감소 정지, 경계에서 이어지는 꼬리, 긴 시간에도 일정한 이동 속도, 광원 방향과 효과 생성 비용이다. 기존의 느린 선단을 기대하던 테스트는 새 사용자 요청에 맞춰 즉시 연결을 검사하도록 수정했다.

작성 범위: `src/render/beams.js`, `entities.js`의 광원 함수, `renderer.js`의 광선·광원·목표 파티클 연결부, `targetFx.js`의 깨어남 시각과 불필요한 지연 필터, `src/game/game.js`의 발사 길이 제어, `tests/beamContact.test.mjs`.

실제 플레이 화면의 강도·가독성은 부모 에이전트가 기존 Ego 공간에서 확인한다. 이 문서는 구현 기록이며 최종 독립 검토를 대체하지 않는다. 이 작업자는 커밋이나 푸시를 실행하지 않았다.
