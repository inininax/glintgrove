# 빛 접촉 표현 독립 검토

2026-09-13 · 검토자: 게임 기획 에이전트 · 작성자: 별도 빔 구현 에이전트

검토 대상은 `src/render/beams.js`, `src/render/targetFx.js`, `src/render/renderer.js`, `tests/beamContact.test.mjs`의 이번 빔 패치다. 검토자가 작성한 장치 안내·색 표식 코드는 이 승인 범위에 포함하지 않는다.

코드 검토에서 배포를 막는 논리 결함은 발견하지 않았다. 목표의 실제 광학 중심까지 그리는 표현과 문 앞 봉인에서 멈추는 표현을 트레이서의 판정과 분리했다. 빛 선단은 이미 계산된 시뮬레이션 경로를 따라가며, 교차하는 빛이 다른 경로의 등장 시간을 당기지 않도록 방향과 색을 함께 연결한다. 포털은 들어간 방향을 유지한다. 새로운 도착 후광은 현재 연결과 올바른 색을 요구하며, 과거에 한 번 깨어났다는 사실만으로 성공 표시를 유지하지 않는다. 재연결 효과는 보상이나 힌트 계산을 건드리지 않는다.

검토자가 별도로 실행한 `node --test tests/beamContact.test.mjs tests/backgroundMotion.test.mjs tests/engine.test.mjs tests/render.test.mjs`에서 26개 테스트가 통과했다. 모든 300개 캠페인의 초기/완료 경로, 네 방향 수신점, 막힌 문, 갈림·교차·색 변화·포털·루프, 재연결, 잘못된 색, 모션 끔과 그리기 순서가 포함된다.

## 도착 시점 추가 패치 검토 — 2026-09-14

처음 검토에서 발견한 생명 아트·문 열림과 빛 선단의 시점 차이는 후속 표현 패치로 해결했다. `gateIsReached`는 해당 색의 입사 구간이 실제로 모두 표시된 뒤에 문을 연다. `TargetContactFx.visualAwakened`는 최초 화면 도착 시각을 별도로 기록하여 생명의 깨어난 아트와 팝 동작을 맞춘다. 논리 보상 시각은 변경하지 않고, 진행 중 경로 변경에서는 이미 깨어난 외형을 보존한다. 같은 파싱 객체를 재사용하는 재시작도 `litAt`의 삭제·새 시각으로 구별한다.

기존 목표 파티클은 입사 전 태어난 경우 그리기 대상에서만 제외한다. `ParticleSystem`의 `x/y`는 이동한 위치가 아니라 고정 출발점이며 이동은 `draw`에서 적용되므로, 현재 출발점 비교는 이 시스템과 일치한다. 파티클과 게임의 시간은 같은 `dt`를 사용한다. 필터는 원본 배열이나 입자를 변경하지 않고 다른 광원 파티클은 유지한다.

추가 3개 테스트와 관련 회귀 테스트를 독립 실행했다. `node --test tests/beamContact.test.mjs tests/backgroundMotion.test.mjs tests/engine.test.mjs tests/render.test.mjs tests/ui.test.mjs tests/i18n.test.mjs`에서 총 43개가 통과했다. 이번 추가 패치에서 차단 결함은 발견하지 않았다. 이전의 도착 전 깨어남·문 열림·목표 파티클 항목은 코드와 테스트 기준으로 해결됨으로 판정한다. 실제 애니메이션의 속도와 강도는 부모 에이전트의 최종 브라우저 검수 범위다.
